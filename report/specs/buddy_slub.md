# 小组扩展：Buddy 与 SLUB spec

基准：小组 lab2 分支 `7281d3b`；原始任务描述见 [prompt.md](../prompt.md)。

## Buddy

- `free_area[k]` 管理 `2^k` 页且按该大小对齐的空闲块，k 为 0 到 31。
- 初始化连续空闲区时，根据页号对齐与剩余页数贪心拆成若干块。
- 分配请求向上取整为 2 的幂，从对应阶向上寻找；将较大块逐次二分。
- 非 2 的幂请求例如 7 页占用 8 页，释放时由同一规则还原长度。
- 释放使用物理页号 XOR 块大小定位伙伴；伙伴范围合法、空闲且同阶时继续合并。
- 空闲统计为各阶空闲页数总和，分配与释放恢复相应计数。
- 正常构建与 `ucore_test` 构建选择 Buddy，`LAB2_GRADE` 构建选择 Best-Fit。

## SLUB

- 小对象档为 8、16、32、64、128、256、512、1024、2048 字节，向上取档。
- 每个 slab 使用一页，元数据存在 `Page` 中，空闲对象内存储下一对象指针。
- 分配从头弹出对象；释放压回对象；全部对象释放后将整页交回底层分配器。
- 超过 2048 字节的请求向上按页取整，调用当前页分配器，并在页头记录请求页数。
- `alloc_pages(n)` 通过 SLUB 的大对象路径分流，返回结果再转回 `Page *`。
- `slub_alloc(0)` 触发断言；超大请求返回 `NULL`；`slub_free(NULL)` 无操作。
- 释放要求传入仍有效的分配起始指针。

## 验收

`make test` 定义 `ucore_test`，编译并运行小组的 `test_buddy_system()` 和 `slub_check()`。两者应输出 `ALL PASS`，释放全部测试分配后空闲页数恢复。正常测试组包含超额请求和 NULL 释放。
